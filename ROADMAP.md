# Development roadmap

This roadmap describes intended work, not completed features or delivery commitments.

## Phase 1 — Public documentation (started)

- [x] Establish an independent public repository.
- [x] Document purpose, workstreams, contribution process and security contact approach.
- [ ] Inventory existing Mauritius.Name components and determine which may be published.
- [ ] Verify authorship, third-party licences, privacy and security before releasing code.

## Phase 2 — Reusable civic consultation components (planned)

- [ ] Publish reviewed installation and configuration instructions.
- [ ] Prepare a minimal, non-production demonstration of a legislative reader.
- [ ] Provide a structured way to submit proposed amendments.
- [ ] Add accessible and mobile-friendly interaction patterns.
- [ ] Publish only synthetic sample data and anonymised examples.

## Phase 3 — Openness and accountability (planned)

- [ ] Document moderation and data-retention practices.
- [ ] Explore multilingual support and accessibility testing.
- [ ] Consider structured exports of public proposals where consent and rights permit.
- [ ] Add automated tests and security checks for released code.

## Release criteria

Before source publication: remove secrets and personal data; check ownership and dependencies; assess legal and security risks; choose a suitable licence; verify that documentation reflects actual functionality.

Feedback and issue reports are welcome. No feature in this roadmap should be understood as already deployed unless independently documented.
